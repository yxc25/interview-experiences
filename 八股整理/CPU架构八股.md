## ⁠1. ARM架构
### ⁠1.1. 什么是ARM架构
ARM属于RISC架构，指令定长（有32位和64位的体系架构）、格式规整，硬件解码简单。这带来了更高的能效比，即每瓦性能出色，非常适合电池供电的设备。
ARM 架构的“规则”本质上是一套分层的抽象行为契约，它不规定具体的电路实现，而是定义了处理器必须遵守的指令集架构（包括有哪些指令、编码格式、寻址模式）、程序员模型（通用寄存器、SP、LR、PC 的组织，特权级别划分）、内存模型（4GB 统一编址、对齐要求、访问属性）、异常与中断模型（异常类型、优先级机制、入口与返回流程），以及一系列可选扩展的“插槽”——比如 DSP 指令、浮点单元 FPU、TrustZone 安全扩展、MPU 内存保护单元等，架构只规定“如果实现了这个扩展，行为应该是什么样”，是否实现则由芯片厂商根据应用场景决定。
### ⁠1.2. ARM架构有几种工作模式
嵌入式固件常用的 M-Profile 只有线程模式和处理模式两种。线程模式（Thread Mode） 是跑“正常代码”的地方——main()、RTOS 任务、普通业务逻辑；处理模式（Handler Mode） 是跑“异常代码”的地方——所有中断服务程序（ISR）和异常处理程序。
### ⁠1.3. 什么是栈指针
栈指针是一个寄存器，里面存着当前栈顶的内存地址。CPU 压栈（PUSH）时，SP 自动减小；出栈（POP）时，SP 自动增大。它让 CPU 知道“下一个数据该放哪、该从哪取”。栈是一块后进先出（LIFO） 的内存区域。
### ⁠1.4. 什么是内存对齐
内存对齐是指数据在内存中的起始地址必须是某个值的整数倍。比如一个 4 字节的 int，它的起始地址必须是 4 的倍数（0x1000、0x1004、0x1008…），不能放在 0x1002 这种地址上。

### ⁠1.5. 什么是load/store架构
只有专门的加载（Load）和存储（Store）指令才能访问内存，所有算术运算都必须在 CPU 寄存器之间进行。 换句话说，CPU 不能直接对内存里的数做加法，必须先把它 Load 到寄存器，算完再 Store 回去。
### ⁠1.6. 为什么设计load/store架构
⁠⁠如果允许运算指令直接操作内存，CPU 需要在一个时钟周期内完成“取指→译码→取内存操作数→运算→写回”，流水线会变得非常复杂。Load/Store 架构把访存和运算分离，每条指令只做一件事，流水线设计简单，主频容易做高。简单的指令解码逻辑意味着更少的晶体管、更低的功耗，这是 ARM 统治移动端的重要原因。
### ⁠1.7. 什么是LR寄存器
LR 是 Link Register，专门存放函数返回地址。执行 BL 指令时硬件自动把下一条指令地址写入 LR，RET 时从 LR 跳回。但如果函数还会调用其他函数，LR 会被覆盖，所以必须在入口把 LR 压栈保存。
### ⁠1.8. 什么是PC寄存器
PC （ Program Counter）是程序计数器，保存下一条要执行的指令的地址。 CPU 每执行完一条指令，PC 自动增加（指向下一条），从而实现程序的顺序执行。
### ⁠1.9. 什么是SP寄存器
SP 指向当前栈顶。 压栈时 SP 减小，出栈时 SP 增大。Cortex-M 有 MSP 和 PSP 两个，处理模式永远用 MSP，线程模式由 CONTROL 寄存器决定用哪个
### ⁠1.10. RTOS,FreeRTOS是什么，区别是什么
RTOS（Real-Time Operating System，实时操作系统） 是一种保证任务在规定时间内完成的操作系统。它的核心不是“快”，而是“确定性”——任务从触发到执行的时间是可预测的。

FreeRTOS 是 RTOS 中最流行、最开源、最轻量的一个实现，专门为微控制器（Cortex-M 等）设计，广泛应用于嵌入式固件开发。
### ⁠1.11. RTOS 如何保证实时性
RTOS 保证实时性靠的是抢占式优先级调度、确定性调度器、极短的中断延迟、优先级继承防翻转，以及确定性的时间管理。核心不是快，而是可预测——最坏情况下的响应时间是可计算的。嵌入式需要实时性，是因为它直接控制物理世界，刹车、电机、医疗设备都有硬性截止时间，错过就是灾难。裸机主循环无法保证高优先级事件及时响应，而 RTOS 让关键任务随时抢占，同时用多任务结构把复杂逻辑拆开，保证确定性的同时提升可维护性。
### ⁠1.12. 什么是公平调度机制的操作系统
公平调度机制的目标是让每个任务都能“公平地”分到 CPU 时间，不追求某个任务最快响应，而是追求整体吞吐量和长期公平性。所以公平调度和 RTOS 调度是两种相反的设计哲学：一个追求公平，一个追求确定性。
### ⁠1.13. Cortex-M 和 ARM 架构什么关系
ARM 架构是 ARM 公司定义的指令集和处理器设计规范，Cortex-M 是 ARM 公司基于 ARMv6-M / v7-M / v8-M 这些具体架构版本，面向微控制器场景设计的处理器核心系列。芯片厂商拿到 Cortex-M 的 IP 核后，加上自己的存储和外设，做成 MCU。所以我们写的 STM32 固件，底层跑的就是 Cortex-M3/M4 这类内核。
