## ⁠1. C语言概念知识
### ⁠1.1. 什么是堆和栈
堆和栈是C程序运行时内存中的两个核心区域：栈由编译器自动管理，用于存放局部变量、函数参数和返回地址，遵循后进先出原则，分配释放极快但空间有限，函数返回时自动回收；堆则由程序员手动管理（如 malloc/free），空间大、生命周期灵活，可跨函数存活，但分配较慢且需自行释放，否则会造成内存泄漏。简单说，栈是自动、快速、临时的内存区，堆是手动、灵活、需谨慎管理的动态内存区。
### ⁠1.2. 什么是内存泄漏，内存泄漏会带来什么影响

内存泄漏是指程序用 malloc 等函数在堆上申请了内存，用完后却忘记 free，导致这块内存既无法被程序再访问，也无法被系统回收。它的危害是“慢性”的：程序内存占用会随运行时间不断增长，可用内存越来越少，堆碎片增多使程序变慢，最终 malloc 失败返回 NULL，若未检查就会导致段错误崩溃

### ⁠1.3. C语言代码编译的过程是怎么样的

C语言代码的编译过程分为四个阶段：预处理阶段展开头文件、替换宏、处理条件编译，生成 .i 文件；编译阶段把C代码翻译成汇编代码，生成 .s 文件；汇编阶段把汇编代码逐条翻译成机器指令，生成 .o 目标文件；链接阶段把多个目标文件和库文件合并，解析符号、重定位地址，最终生成可执行文件。平时一条 gcc main.c -o main 命令，背后就是 gcc 自动依次调用预处理器、编译器、汇编器和链接器完成这四个步骤。
### ⁠1.4. 交叉工具链是干什么的
交叉工具链是指在一个平台上（如 x86 架构的 PC）编译、链接出能在另一个不同平台上（如 ARM、MIPS、RISC-V 架构的开发板或嵌入式设备）运行的程序的一套完整开发工具集合，通常包括交叉编译器（如 arm-linux-gcc）、交叉链接器、交叉汇编器以及相关的库和头文件。它的核心作用是解决目标平台资源不足、无法本地编译的问题：嵌入式设备往往 CPU 性能弱、内存小、没有操作系统或缺乏完整开发环境，根本无法运行编译器；而 PC 性能强大、工具完善，因此我们在 PC 上借助交叉工具链完成编译，生成目标平台能执行的二进制文件，再烧录或传输到设备上运行。一句话概括：交叉工具链就是“在 A 平台编译、让 B 平台运行”的桥梁，是嵌入式开发和跨平台移植的基础工具。
### ⁠1.5. 局部变量和静态变量的区别在哪
局部变量存在栈上，随函数调用而生、随函数返回而灭，作用域和生命周期都限于函数内；静态变量存在静态存储区，程序运行期间一直存在，只初始化一次，静态局部变量作用域仍在函数内但能跨调用保留值，静态全局变量则把作用域限制在当前源文件内。
### ⁠1.6. 有没有遇到程序崩溃的现象
程序崩溃是程序因内存错误、非法操作等原因被操作系统强制终止的现象，最常见的是段错误。它会带来功能中断、数据丢失、资源泄漏、服务雪崩等严重后果，在服务器和嵌入式场景下危害尤其大；而且崩溃往往难以复现和定位，因此需要通过防御性编程、工具检测、日志和容错设计来预防和应对。
### ⁠1.7. 什么是数组越界，数组越界会造成什么
数组越界是访问了数组范围外的内存，C语言不做检查，后果从“读到垃圾数据”“悄悄改坏相邻变量”到“破坏栈帧或堆结构导致段错误崩溃”都有可能；最危险的是它不一定立刻崩溃，而是埋下难以定位的内存踩踏隐患。
### ⁠1.8. 文件系统了解吗
文件系统是操作系统管理存储设备上数据的机制，它通过目录树、索引结构和元数据，把杂乱的存储空间组织成可按名字访问的文件和目录；它决定了数据怎么存、怎么找、怎么读写，是操作系统和存储设备之间的“管理层”。不同平台和场景（Windows、Linux、嵌入式 Flash）会使用不同的文件系统。
### ⁠1.9. 什么是进程和线程
进程是操作系统资源分配的基本单位，拥有独立的地址空间和资源，隔离性强但开销大；线程是CPU调度的基本单位，是进程内的执行流，共享进程资源，轻量高效但隔离性弱、同步复杂。一个进程可以包含多个线程，二者共同构成了操作系统的并发执行模型。
### ⁠1.10. 进程间如何实现通信效果
进程间通信IPC是操作系统为独立地址空间的进程提供的交换数据和协调动作的机制，常见方式包括管道、消息队列、共享内存、信号、信号量和 Socket；其中共享内存最快但需自己同步，Socket 最通用可跨网络，管道最简单适合父子进程，实际开发中常根据数据量、速度、隔离性和是否跨主机来组合选用。
### ⁠1.11. C语言间如何实现进程通信
C语言实现进程间通信（IPC）的核心，是借助操作系统提供的系统调用，在相互隔离的进程地址空间之间建立数据通道或同步机制。具体来说：管道通过 pipe() 创建内核缓冲区，配合 fork() 让父子进程以 read()/write() 进行单向字节流通信；消息队列用 msgget()/msgsnd()/msgrcv() 在内核中维护带类型的数据块，接收方可按类型筛选；共享内存通过 shmget() 和 shmat() 把同一块物理内存映射到多个进程的地址空间，实现零拷贝的高速数据交换，但必须配合信号量（semget()/semop()）做 P/V 操作来保证互斥与同步；信号用 sigaction() 注册处理函数、kill() 发送通知，只能传递信号编号，适合异步控制；套接字则通过 socket()/bind()/connect()/send()/recv() 提供最通用的全双工通道，既能本机通信也能跨网络。实际开发中，通常根据数据量、速度要求、是否需要跨主机以及同步复杂度来组合选用这些机制——例如高性能场景用“共享内存+信号量”，跨网络场景用 Socket，父子进程简单通信用管道。
### ⁠1.12. 板间的通讯方式有哪些
最常用的是基于串行总线的协议：
SPI（Serial Peripheral Interface）是四线同步协议，速度快，适合板间高速数据传输。实际应用中通常将一个板配置为 Master，另一个为 Slave，通过 MOSI、MISO、SCK、CS 四根线连接，双方 GND 必须共地。SPI 支持 DMA 和中断方式，适合数据量较大的场景。

I2C（Inter-Integrated Circuit）是两线同步协议，只需 SDA（数据）和 SCL（时钟）两根线，支持一主多从，每个从设备有唯一地址。速度比 SPI 慢，但引脚占用少，适合连接多个低速外设或传感器。

UART（通用异步收发器）是两线异步协议，仅需 TX 和 RX，无需时钟线，但双方必须约定相同的波特率。适合点对点简单通信，也是连接无线模块（如 ESP32）与主控板之间的常见桥梁。

以太网（Ethernet）通过 RJ45 网口或板间高速连接器实现，支持千兆速率，适合需要高带宽和远距离传输的场景，嵌入式系统中常用 SGMII 模式来简化板间互连。

高速串行总线如 PCIe、SRIO、Aurora 等，用于 FPGA 芯片间或板间的高性能通信，通过 SerDes 实现吉比特级速率。
### ⁠1.13. 什么是内核态，什么是用户态
用户态是程序受限运行的普通状态，只能访问自己的地址空间、不能直接操作硬件；内核态是CPU的最高权限状态，可以访问全部内存和执行特权指令。程序平时跑在用户态，当需要读写文件、操作设备、申请内存时，通过系统调用、中断或异常切换到内核态，由内核代为完成后再返回用户态。这种分级机制是操作系统安全与稳定的基石。
### ⁠1.14. 如何实现内核态和用户态的切换
内核态和用户态的切换由系统调用、中断、异常三类事件触发，核心是 CPU 通过特权指令（如 syscall）从 Ring 3 进入 Ring 0，硬件自动保存用户态现场、切换到内核栈、跳转到内核入口；内核处理完后再通过 sysret/iret 恢复现场并切回用户态。整个过程的关键在于特权级切换、栈切换和现场保存恢复，由硬件和操作系统内核紧密配合完成。
### ⁠1.15. 嵌入式开发为什么多用C语言进行开发
嵌入式用C，是因为它能直接操作硬件、资源占用小、实时性可控、生态成熟；而Python等语言因为需要运行时、内存开销大、无法直接控制硬件、实时性差，在资源受限和硬实时场景下不适用。C++、Rust在特定场景可用，但C仍是嵌入式开发的绝对主力。
### ⁠1.16. 什么是解释型和编译型语言
编译型语言在运行前把源代码整体翻译成机器码，执行快但需提前编译；解释型语言在运行时逐行翻译执行，灵活但慢。C 属于编译型，Python 属于解释型，Java/JS 则是混合型。嵌入式因为资源受限、要求高效，所以用编译型的 C。
### ⁠1.17. 为什么C语言是面向过程的语言，C++是面向对象的语言
C 是面向过程的语言，以函数和数据结构为中心，数据与操作分离；C++ 是面向对象的语言，把封装、继承、多态做进了语言本身，让数据和操作绑定、支持复用和运行时多态。C 并非不能面向对象，而是没有原生语法支持，只能用结构体和函数指针手动模拟，繁琐且易错；C++ 则让编译器自动处理这些机制，使大型软件的组织和维护变得更容易。这正是两者设计目标和语言哲学的差异。
### ⁠1.18. 封装、继承和多态
封装是把数据和操作捆绑并控制访问，保护内部状态；继承是子类复用父类的属性和方法并扩展自己，实现代码复用；多态是同一接口在不同对象上表现出不同行为，通过虚函数在运行时决定调用哪个实现。三者层层递进，共同构成了面向对象编程的基石，让代码易维护、可复用、可扩展。
### ⁠1.19. C语言中的关键词
static：核心是改变变量的生命周期和链接属性——修饰局部变量时让它存于静态存储区，函数返回后值不销毁且只初始化一次；修饰全局变量或函数时，把作用域限制在当前源文件内，避免跨文件命名冲突，是模块化设计的重要手段。

volatile：告诉编译器不要优化对该变量的访问，每次都必须从内存地址重新读取，而不是缓存到寄存器里；主要用于硬件寄存器、中断修改的全局变量和多线程共享变量，但它只阻止优化，不保证原子性和线程安全。

const：本质是“只读”而非真正的常量，修饰变量时值不能被直接修改，修饰指针时要区分 const int *p（指向内容不可改）、int * const p（指针本身不可改）和两者都不可改的情况；修饰函数参数可表明函数不会修改传入对象，提高安全性和可读性。

extern：用于声明变量或函数是在其他文件中定义的，本身不分配内存，只是告诉编译器“这个符号在别处存在”；它让符号对全局可见，和 static 的限制作用域正好相反，是实现跨文件引用的关键。
## ⁠2. C语言调试

### ⁠2.1. C语言的程序是如何进行debug的
通过打断点与单步调试进行的
断点的原理是把目标指令首字节替换成 0xCC（INT 3），CPU 执行到就触发异常，把控制权交给调试器；硬件断点则靠 CPU 调试寄存器比较地址，不改代码但数量有限。单步执行靠 CPU 的 TF 标志，每执行一条指令就触发一次异常；源码级的 step/next 则是在函数入口或下一行设临时断点，结合指令级单步实现。它们的共同本质都是：利用 CPU 的异常机制，在指定位置让程序停下来，交给调试器控制。
### ⁠2.2. 什么是GDB调试工具
GDB 是 Linux 下的命令行调试器，通过打断点、单步执行、查看变量和调用栈来跟踪程序运行；编译时加 -g 生成调试信息，运行时可以本地调试、attach 到进程或分析 core dump。它是 C 语言排查逻辑错误和崩溃问题的核心工具，也是你之前用的“断点 + 单步”背后的那套系统。
### ⁠2.3. 如果程序烧录进嵌入式开发板的时候出现了问题，你应该如何排查，这个过程是怎么样的

程序烧录失败时，核心排查思路是：
先确认硬件连接和供电是否正常：确认调试器（如 J-Link、ST-Link、DAP）是否亮绿灯，确认嵌入式开发板的供电是否正常，确保电源的稳定性
再检查芯片是否被“锁住”或处于异常状态：看许多 MCU的BOOT 引脚的状态，复位嵌入式开发板
最后排除软件配置问题：看烧录的算法是否争取，文件路径是否正确等等。
